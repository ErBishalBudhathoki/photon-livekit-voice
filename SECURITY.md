# Security model

This stack holds credentials for a phone line and a model API, and it records
conversations. What follows is what lives where, what must never be published, and
what to do when something leaks.

## What holds a secret

| Where | What | Mode |
| --- | --- | --- |
| `.env` | LiveKit key/secret, model API key, SIP trunk credential, provider key, owner's number | `600`, gitignored |
| `certs/` | TLS certificate and its private key | directory `700`, key `600`, gitignored |
| `calls/*.jsonl` | transcripts: real conversations with real numbers | gitignored |
| `livekit.yaml`, `sip.yaml`, `docker-compose.yaml` | rendered from templates, contain the LiveKit secret | `600`, gitignored |
| provider dashboard | the SIP line, its inbound destination, the outbound credential | not on this host |
| `.secretscan` | this install's identifiers used by the scanner | `600`, gitignored |

Everything above is generated by the bootstrap scripts. Every script that writes
`.env` chmods it to `600` in the same step (`10-stack.sh`, `20-sip-objects.py`,
`30-photon.py`); `cert-acme.sh` chmods the key. Nothing is written with default
permissions.

## What is never published

`.gitignore` excludes the lot, and `scripts/secret-scan.py` enforces it against
what git would actually push:

```bash
python3 scripts/secret-scan.py            # files + full history
python3 scripts/secret-scan.py --staged   # exactly what a commit would add
```

It fails on four things: a credential-shaped string (`AIza…`, `sk-…`, `ghp_…`,
`AKIA…`, private key blocks, `Bearer …`, long hex/base64), a forbidden filename
(`.env`, `*.pem`, `certs/`, `calls/`, `*.jsonl`, `id_rsa`), a live value from your
own `.env` appearing anywhere in the tree, and the same in any past commit.

`.secretscan` (gitignored) is where you list install identifiers you never want to
publish — your domain, public IP, provider project id, phone number. Keep them out
of tracked files and the scanner will catch it if one slips in.

Hooks and CI:

```bash
bash scripts/install-hooks.sh     # pre-commit: --staged, pre-push: full scan
```

`.github/workflows/secret-scan.yml` runs the same scanner on every push and PR, so
a local hook bypassed with `--no-verify` still cannot land a secret.

## Rotation

Rotate in this order; each step is safe to stop at.

1. **Provider API key** — issue a new one in the dashboard, put it in `.env`.
2. **SIP trunk credential** — `python3 bootstrap/20-sip-objects.py` generates a new
   credential (delete `SIP_INBOUND_USER`/`SIP_INBOUND_PASS` first), then
   `python3 bootstrap/30-photon.py` pushes it to the provider.
3. **Model API key** — new key in `.env`, `systemctl --user restart livekit-agent`.
4. **LiveKit key/secret** — regenerate both in `.env`, then
   `bash bootstrap/10-stack.sh` (it re-renders `livekit.yaml`, `sip.yaml` and the
   compose file from the templates) and restart the unit.
5. **TLS key/cert** — `bash bootstrap/cert-acme.sh`, then restart `livekit-sip`.

Restarting the worker mid-call drops the call. Nothing else needs a reboot.

## If a secret was published

Rotate it first — history rewriting does not un-publish anything that has already
been fetched, mirrored or indexed. Then remove it from history
(`git filter-repo --path .env --invert-paths`, or BFG), force-push, and re-run
`python3 scripts/secret-scan.py` to confirm the history is clean. Treat a pushed
credential as compromised even if the repo was private and short-lived.

## Delegation and transcripts

- Transcripts are conversations. They stay in `calls/`, which is gitignored; the
  chat surface reads them locally and posts a briefing, it never uploads them.
- Delegation (letting a caller drive tools) ships **off**. Turning it on requires
  an explicit caller-ID allowlist — anyone who can spoof a caller ID must not be
  able to reach a tool.
- Inbound calls are authenticated by the trunk credential, not by caller ID.

## Reporting

Open a private security advisory on the repository (Security → Report a
vulnerability) rather than a public issue. Do not include a live credential in the
report; a description and a redacted log line are enough.
